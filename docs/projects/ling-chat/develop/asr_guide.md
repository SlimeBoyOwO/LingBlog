# 语音识别使用指南

> 适用版本：含语音输入功能的桌面版本（设置 → **语音识别** 面板）。

## 介绍

本功能为LingChat的**语音识别功能**：既可以对接阿里云 DashScope 在线识别，也可使用**双击即用的本地推理一键包**（llama.cpp + Qwen3-ASR 0.6B），支持按住说话、自动监听、实时流式出字，实现只需说话即可聊天的语音输入功能。

识别服务（阿里云在线 / 本地推理）在设置内**一键切换**，互不绑定；下文的快速上手会先带你在 3 分钟内清楚基本使用流程，第 2~4 章深入讲解模型配置、每个设置项的含义与界面按钮行为，常见问题见第 5 章。

## 1. 快速上手

语音输入 = **软件功能** + **一个识别服务**，服务二选一：

| | 阿里云在线识别 | 本地识别（llama-server） |
|---|---|---|
| 是否要注册/联网 | 要（DashScope API Key，音频上传云端） | 否，完全离线 |
| 花费 | 按量计费 | 免费 |
| 适合 | 无独立显卡、追求最高识别精度 | 绝大多数用户（N 卡 / A 卡 / 核显 / CPU 都行） |

### 方式 A：本地识别（零注册，推荐）

**第 1 步：启动本地推理服务**

打开本地部署包目录（例如 `D:\asr一键API推理包`），**双击 `asr-start.bat`**：

```
Select inference device:
  [1] NVIDIA GeForce RTX 5060 （根据实际型号可能有所不同）      ← 有独显就选它
  [2] Intel(R) Graphics （根据实际型号可能有所不同）           ← 或选核显
  3] CPU (no GPU)
  Your choice (1-3): _
```

- 输入编号回车后，窗口出现 `API : http://127.0.0.1:8080` 即服务就绪
- **关闭这个窗口 = 停止服务**（下次用需重新双击启动）
- 重复启动没关系：脚本会先检查 8080 是否已占用，已在运行会直接提示

> 💡 没有 GPU 就选 CPU 项，0.6B 模型 CPU 识别约 600ms，依然可用。
>
> 📝 用户群内下载

**第 2 步：软件内配置**

1. 打开 LingChat，进入**设置 → 语音识别**
2. 底部确认状态面板显示 **VAD 模型：已加载**（绿色）
3. **识别服务商** 下拉选择 **「本地 ASR（llama-server）」**
4. 服务地址保持默认 `http://127.0.0.1:8080`；模型旁点 **↻ 刷新**，从下拉选中与你部署包一致的模型（本包为 `models/Qwen3-ASR-0.6B-Q8_0.gguf`）
5. 点 **测试连接**：提示「正在录音…请说话（4 秒）」，对着麦克风说一句话，4 秒后自动识别并显示识别结果 = 配置成功

**第 3 步：开始说话**

- 点聊天框上方的 **麦克风按钮**：说话 → 再点一次（或停顿 0.8 秒）→ 文字出现在输入框 → 回车发送
- 或按住 **F8**（默认语音快捷键）：按住说话、松开识别**(0.5.1暂无快捷键输入,后续版本加入)**

### 方式 B：阿里云在线识别

1. 前往阿里云百炼/DashScope 开通语音识别服务并获取 API Key（注册开通流程见下文 2.1 节）
2. LingChat **设置 → 语音识别** → 服务商选择 **「Qwen ASR」**
3. 粘贴 **DashScope API Key**（Endpoint 保持默认）
4. 点 **测试连接** 验证 → 打开 **语音输入** 总开关
5. 使用方式与方式 A 相同

## 2. 进阶使用：识别服务模型配置 {#model-config}

### 2.1 阿里云 DashScope（在线）

**注册阿里云千锤百炼API**
- 阿里云百炼官网:https://bailian.console.aliyun.com
- 登录阿里云百练平台后在常用功能中找到**API Key**创建自己的API key
- 新用户有一定的免费试用额度，可以免费试用，额度用完后找到**费用与成本**界面进行充值即可

配置面板需要理解的概念：

- **两个默认模型，与「流式识别」开关强绑定：**

  | 模型 | 协议 | 流式识别 | 特点 |
  |---|---|---|---|
  | `fun-asr-realtime`（Fun-ASR-Realtime） | HTTP 一次性返回 | 不支持 | 默认，简单稳定 |
  | `paraformer-realtime-v2`（Paraformer-Realtime-V2） | WebSocket 实时 | 支持 | 说话过程中实时出字 |

  打开 **流式识别** 开关会自动切到流式模型，关闭则切回非流式模型（模型与协议一一对应，不要手改成不匹配的组合）。

- **Endpoint（一般无需改动）**：默认 DashScope multimodal-generation 端点；非流式识别走这里。若填了自建代理则整段替换；填 `wss://` 实时地址会导致非流式请求失败——非流式端点只认 http(s)。
- **识别结果的语言**：当前固定由模型自动判断（qwen 接口暂不传语言提示）。
- **费用与隐私**：音频会上传阿里云处理，按量计费，敏感内容请用本地方案。

### 2.2 本地推理包部署（llama-server + Qwen3-ASR）

#### 部署包内容

```
asr一键API推理包\
├── asr-start.bat              # 一键启动脚本（推荐方式）
├── llama-server.exe           # 推理服务主程序（llama.cpp Vulkan 版）
├── ggml-*.dll / llama*.dll    # 运行时库（必须与 exe 同目录）
├── models\
│   ├── Qwen3-ASR-0.6B-Q8_0.gguf        # 主模型（约 805MB）
│   └── mmproj-Qwen3-ASR-0.6B-Q8_0.gguf  # 多模态投影文件（约 214MB，必须与主模型同版本）
├── 部署文档.md                # 面向部署者的完整文档
└── API接入文档.md             # 面向开发者的 API 文档
```

引擎选型为 **llama.cpp Vulkan 版**：一个包通吃 NVIDIA / AMD / Intel（含核显），无需安装 CUDA；CPU 也能跑（启动时选 CPU 即可）。

#### 启动 / 停止

- **启动**：双击 `asr-start.bat` → 按提示选择推理设备 → 保持窗口开着
- **就绪判定**：窗口出现 `API : http://127.0.0.1:8080`；或浏览器访问 `http://127.0.0.1:8080/health` 返回 `{"status":"ok"}`
- **停止**：直接关闭 bat 窗口（服务随窗口结束）；若进程残留，可 `taskkill /f /im llama-server.exe`
- **开机自启（可选）**：把 `asr-start.bat` 的快捷方式放入启动文件夹（Win+R → `shell:startup`）
- **首次使用偏慢（约 8 秒）**：Vulkan 首次推理要编译 shader，属正常现象；之后单次转写 80~200ms

#### 硬件占用与超长音频

脚本已内置 `-c 4096 -np 1` 参数，把显存占用控制在 **约 2.5GB**（默认配置会高达 7.5GB，勿手动去掉这两个参数）：

| 场景 | 显存 | 单次最长音频 |
|---|---|---|
| 当前默认（`-c 4096`） | ~2.5GB | ~5 分钟 |
| 显存紧张（`-c 2048`） | ~2.3GB | ~2.5 分钟 |
| 需要超长音频（`-c 8192`） | ~2.9GB | ~10 分钟 |

聊天场景单句语音远小于 5 分钟，默认足够；超出会返回 HTTP 400（服务不静默损坏）。

#### 在软件中选择模型（重要）

软件启动后会从本地服务动态拉取模型清单（对应 `llama-server` 的 `/v1/models`）：

1. 识别服务商选 **「本地 ASR（llama-server）」**
2. 模型下拉点开，选择**与你部署包内一致**的模型全名（如 `models/Qwen3-ASR-0.6B-Q8_0.gguf`）
3. 若列表为空或报「获取模型列表失败」→ 说明服务未启动或刚重启，先启动 bat，再点 **↻ 刷新**

> ⚠️ 模型名必须与服务端一致（`/v1/models` 返回的全名，`qwen3-asr` 这类简写会 400）。换了模型文件（如升级 1.7B）后，重启服务并在软件里重新刷新选择。

#### 局域网使用（可选）

同一局域网内其它电脑或手机的 LingChat 也能用这台机器的识别服务：bat 启动命令的 `--host 127.0.0.1` 改为 `--host 0.0.0.0`，并在系统防火墙放行 8080；另一端「服务地址」填 `http://<这台机器的IP>:8080`。不建议公网开放。

#### 热词偏置（留后续交由其他开发者接手，暂时未做）

本地引擎支持动态热词（转写请求携带 `prompt` 字段做上下文偏置，能显著提升人名/专有名词识别率）。软件设置页暂未提供输入界面；接口已就绪，可后续版本开放（或手改 `settings.json` 中 `ASR_PROVIDERS.llama-asr.extra.hotwords`，值为逗号分隔的词表，注意改动前先退出软件）。

## 3. 进阶使用：游戏内设置逐项说明 {#settings-details}
**⚠️语音快捷键0.5.1版本未引入**

设置入口：主窗口 **设置 → 语音识别**。以下按页面从上到下逐项说明（改动后自动保存）。

### 1. 语音输入（总开关）

语音输入的总闸。**关闭后一切语音输入不可用**：麦克风按钮禁用、快捷键失效、自动监听停止。新用户默认关闭，需手动开启（开启即触发一次麦克风授权）。

### 2. 语音快捷键（仅桌面端显示）

- **默认键位**：F8（裸键，不带修饰键）。点击按钮进入捕获模式，按下目标键位完成绑定（Esc 取消）；**Enter 不可绑定**（它是聊天发送键）；「恢复默认」一键还原 F8。
- 可绑单键（字母/数字/空格），但**聊天输入框打字时会同时触发**——建议使用功能键或组合键（如 `Ctrl+F8`、`` ` `` 等）。
- **失去焦点快捷键可用（全局快捷键，默认关）**：开启后，LingChat 窗口不在前台时，在任意应用中按快捷键同样触发语音输入（OS 级注册）。注意绑定字母/数字等单键会**拦截其它应用的该键输入**。若注册失败（键被占用等），按钮下方会红字提示原因，此时窗口内的按键监听自动兜底仍可用。
- 安卓端无快捷键输入功能

> 快捷键在聊天页 / 桌宠界面的使用场景见[第 4 章](#button-behavior)。

### 3. 启用自动语音识别（auto_listen，默认关）

开启后自动监听麦克风：**检测到你说话 → 自动开始录音 → 停顿自动结束 → 自动识别**，全程无需按键。与总开关的关系：总开关关时此模式整体停止；此开关只控制「自动监听」模式。

### 4. 静音计时（默认 800ms，可调 100~3000ms）

自动（及手动）模式下，**停止说话后静音多久才算一句话结束**。数值越大越不容易被句中停顿切断，但识别返回更慢。语速慢、爱停顿的用户建议调到 1000~1500ms。

### 5. 能量监测缓冲期（默认 100ms，可调 0~2000ms）

AI 的角色语音（TTS）播放结束后，**隔多久才恢复语音触发**。若 AI 话音刚落，房间环境声立刻触发一次误识别（识别出 AI 自己刚说的话），就把此值调大（如 300~500ms）；设 0 = 立即恢复。TTS 播放期间本身不会触发监听，此值只兜底播放结束瞬间的声音尾巴。

### 6. 识别完成后（send_mode）

| 选项 | 行为 | 适合 |
|---|---|---|
| **填入输入框（推荐）** | 识别文字填入输入框，人工检查后回车发送 | 默认，识别有误可先改再发 |
| **自动发送** | 文字先显示约 0.8 秒，然后自动发送给 AI | 想全语音对话、双手不碰键盘 |

- 自动发送在**发送前会复查**：这 0.8 秒内你若编辑或清空了输入框，就不会自动发送（尊重人工操作，防同一句重复发送）。
- 两种模式都完整走剧本分支：游戏剧情推进中（含剧本自由对话）会正确提交给剧本引擎，不是绕过剧本直接发主对话。

>（自动发送一定要在安静的地方使用，当然你也不想发生一些奇怪的事情吧)

### 7. 识别服务商（provider）

- **服务商下拉**：当前内置两家 —— **Qwen ASR**（阿里云 DashScope，在线）与 **本地 ASR（llama-server）**（本地推理，见[第 2 章](#model-config)）。
- 下方表单字段由所选服务商动态生成，不同服务商字段不同：

  | 服务商 | 字段 | 说明 |
  |---|---|---|
  | Qwen ASR | DashScope API Key（必填） | `sk-` 开头，点击后保存（明文只存后端 `settings.json`，不落前端 localStorage） |
  | | Endpoint | 默认 DashScope 非实时端点，一般不动 |
  | 本地 ASR | 服务地址 | 默认 `http://127.0.0.1:8080` |
  | | 模型 | 下拉选择（自动从服务端拉取）+ ↻ 手动刷新 |
  | | API Key（可选） | 本地服务带 `--api-key` 部署时才需要 |
- **测试连接按钮**：点按后录音 4 秒（显示「正在录音…请说话」），再次点击可提前结束识别，结果会显示在按钮旁。测试**先自动保存当前表单**再发起，所以填写后不用等自动保存即可直接测试。

### 8. 流式识别（默认关）

- 仅当**当前生效模型支持流式**时开关才可操作（不支持时置灰并提示「当前模型不支持流式识别」）。
- Qwen ASR：开启后自动切换到 WebSocket 实时模型（paraformer-realtime-v2），**说话过程中实时显示识别文字**。
- 本地 ASR：开启后是「结果流式」——录音结束后整段上传，结果**逐步**显示（引擎不支持下逐字，语义为增量出字，体验类似打字机）。
- 模型与协议强绑定，设置页会在开关与模型之间自动联动同步。

### 9. 状态面板（页面底部）

- **VAD 模型：已加载/未加载** —— 语音端点检测模型（Silero VAD）的状态。未加载时自动识别模式的「停顿判句」不可用，多为资源文件缺失（可运行项目内 `download_emotion_model` 类脚本重新获取资源）。
- 页面右上角状态：`已就绪`（绿）或 `未配置（错误码）`（红）。红色代表最近一次识别链路失败，**下一次识别成功会自动转绿**；部分错误码含义见[常见问题](#faq)。(0.5.1版本这个有bug，只要测试能用就行)

### 桌宠（宠物模式）

桌宠界面的语音输入与聊天主界面**共享同一套后端设置与服务**（在哪边配置都一样）。桌宠的麦克风按钮悬浮在角色旁：默认透明隐藏，鼠标悬停区域才出现。

## 4. 进阶使用：前端按钮与操作行为 {#button-behavior}

### 4.1 麦克风按钮（手动录音）

位于聊天输入框上方（桌面）与桌宠角色旁。行为随设置变化：

| 设置状态 | 点击行为 | 图标/文案 |
|---|---|---|
| 自动识别**关** + 总开关开 | **切换录音**：点一下开始（蓝灯呼吸动画），再说点一下立即结束识别；或说完停顿 0.8 秒自动结束 | 麦克风图标 |
| 自动识别**开** + 总开关开 | 变为**自动监听功能开关**：监听中点击 = 暂停；暂停时点击 = 恢复监听（识别服务商颜色高亮表示正在监听中） | 麦克风 / 麦克风关闭 |
| 总开关关 | 按钮禁用 | — |

手动录音要点：

- **识别中（recognizing）按钮禁用**：语音正在识别时点击无任何分支可走，属预期行为
- 录音期间**输入框只读**（防止击键声混入麦克风采样）；输入框里有草稿时，手动录音的识别结果会**追加**在草稿之后（边想边说、连续补录的场景）；自动监听模式的结果则是替换
- 录音有 **60 秒硬上限**，到点自动结束识别
- 录音期间切走界面/打开设置抽屉 = 本次录音丢弃不识别（识别在飞的则等结果返回后丢弃，不会把你没说完的话发出去）

### 4.2 什么情况下麦克风点不了（可用性门控）

按钮变灰/静默无响应，通常是以下场景之一（都是有意设计）：

1. **AI 正在回复**（思考中/回复中/演出展示中）
2. **角色语音（TTS）正在播放**（外放会被麦克风误识别成你自己说话）
3. 启动加载动画未完成
4. **剧本选择分支弹出**（选项按钮出现时）
5. 不在聊天界面 / 设置抽屉打开 / 移动端菜单展开
6. 触摸模式（移动端）
7. 语音识别结果刚填入输入框的短暂窗口（400ms 防抖；手动点击不受此限）

> 若你觉得「没道理点不了」，如果卡死可以点开设置重新开关ASR总开关或者重启游戏。(可在开发者工具控制台(F12打开)查看带 `[ASR]` 前缀的诊断日志，`start 被门控拒绝` 会打印具体原因)

### 4.3 语音快捷键（PTT，按住说话）

默认 **F8**，桌面端在聊天与桌宠界面均生效（窗口内按键）：

- **自动识别关**：按住说话 → 松开即识别（不丢首字，按下瞬间即开始录音）；**快速单击（250ms 内松开）= 锁定持续录音**（toggle-held，方便说长句），再按一下停止
- **自动识别开**：快捷键转为**切换自动监听的开关**（暂停/恢复运行态，不改动设置）
- 按住期间**窗口失焦**：视手势处理 —— 按住中失焦会丢弃本次录音（避免把环境声送去识别）；锁定持续录音中失焦则**保留录音**（回到窗口后按一下快捷键即可正常停止）
- 路由离开聊天/桌宠页时按键不生效（不会在别的界面误启动）

### 4.4 全局快捷键（失去焦点可用）

设置页开启「失去焦点快捷键可用」后（见[第 3 章](#settings-details)的「语音快捷键」一项），任意应用前台按快捷键都能触发：按下事件直接驱动录音状态机，行为与窗口内按键一致（含上面说的单击锁定）。释放事件由 OS 级回调保证到达，不会因焦点丢失卡住录音。

### 4.5 自动识别（auto_listen）模式全流程

开启后完整的自动化闭环：

```
AI 说完话（TTS 结束）→ 缓冲 100ms → 持续能量监测
    → 检测到人声（能量超过阈值）→ 自动开始录音（后台 VAD 端点检测）
    → 停顿达「静音计时」→ 本轮结束 → 整段识别
    → 按「识别完成后」模式：填入输入框 / 自动发送
    → 继续下一轮监测
```

- 录音只录「能量触发后」的语音段（裁剪首尾静音再送识别）
- AI 角色语音播放期间监听自动暂停（门控），不会录进 AI 的话
- 60 秒硬上限同样生效
- 在「填入输入框」模式下，自动识别结果会**替换**输入框现有内容（区别于手动模式的追加）；显示后短暂锁定，防止连续识别立刻覆盖刚填入的文字，等你编辑
- 中途切界面/开设置 = 监听暂停（回来需点一下麦克风恢复）；总开关关 = 整个模式停止

## 5. 常见问题处理 {#faq}

### 服务与配置类

| 症状 | 原因与解决 |
|---|---|
| 设置页显示「未配置（ASR_MISSING_CREDENTIALS）」 | 当前服务商没填 API Key：Qwen ASR 必填 DashScope Key；本地 ASR 不需要 Key，检查是否选错了服务商 |
| 测试连接提示「请求失败 / connection refused」 | 本地服务没启动：双击 `asr-start.bat` 并等窗口显示 API 就绪；或服务地址填错（检查端口 8080） |
| 测试连接提示「无法从响应中提取文本」 | 服务地址或模型与服务端不匹配：用 `/v1/models` 核对模型全名，点 ↻ 重新拉取并选择 |
| 模型下拉为空 / 「获取模型列表失败」 | llama-server 未启动或刚重启：先启动服务再点 ↻ 刷新 |
| 本地识别报 HTTP 400 | 模型名用了简写（需 `/v1/models` 全名）或音频超过上下文上限（聊天语音不会触达，正常使用无需处理） |
| 切换服务商后识别仍走旧的 | 等待 0.5 秒自动保存完成再操作；测试连接会先保存再发起，不存在此问题 |
| VAD 模型显示「未加载」 | 资源文件缺失，自动识别模式的判句不可用；重新执行资源准备脚本（见项目 README 初始化流程） |

### 识别效果类

| 症状 | 原因与解决 |
|---|---|
| 识别经常被停顿切断 | 调大**静音计时**（如 1200ms） |
| AI 话音刚落就被误触发（识别出 AI 的话） | 调大**能量监测缓冲期**（如 300ms） |
| 人名/专有名词/游戏术语识别错 | 本地引擎支持热词偏置（见 2.2 节）；云引擎目前无热词入口，可换用本地方案 |
| 中英混杂识别差 | 引擎按整段自动判语言，极短句（<1 秒）可尝试说得稍完整些 |
| 录音明明有声音却识别为空 | 环境噪声大/离麦远 → 靠近说话；音量正常仍为空可换服务商对比 |
| 识别结果返回很慢 | 本地首次请求 8 秒属正常预热；此后 GPU 80~200ms；云服务受网络影响 |

### 按钮与交互类

| 症状 | 原因与解决 |
|---|---|
| 麦克风按钮是灰的 | 总开关没开；或处于 4.2 节任一场景（AI 回复中 / TTS 播放 / 剧本选项等），等几秒再看 |
| 点了麦克风没反应（不灰但不动） | 录音已在进行？再点一次=停止；或麦克风权限被系统拒绝（见下条） |
| 提示麦克风权限被拒绝 | 在系统设置里给 LingChat 开启麦克风权限，重启软件；Windows：设置 → 隐私和安全性 → 麦克风 |
| 同一句话发了两次（旧版本） | 已知问题：自动发送窗口内手动按了回车会双发，已在修复版本中处理；升级即可。当前版本若输入框内容不是识别结果，不会自动发送 |
| 快捷键按了没反应 | 确认总开关开、在聊天/桌宠界面、AI 空闲；捕获绑定的是否被其它应用占用（全局快捷键场景）；输入法/游戏独占键盘会吞键 |
| 快捷键松开后录音不结束 | 属旧版缺陷（锁定状态失焦导致），升级版本；当前版本按住中失焦会丢弃录音，不会卡住 |
| 桌宠模式找不到语音设置 | 桌宠设置里暂无该页，请在主窗口 设置 → 语音识别 配置（两端共享同一配置） |

### 资源与隐私类

| 问题 | 说明 |
|---|---|
| 本地方案资源占用 | 默认约 2.5GB 显存 / 2.3GB 内存（0.6B 模型）；纯 CPU 约占用 2GB 内存 |
| 想完全离线 | 用本地服务商即可；阿里云方案会上传音频 |
| 云方案费用 | 按识别时长计费，具体见阿里云计费页 |
| 本地模型可否升级 | 支持替换成同系列更大模型（如 1.7B Q8_0），需下载主模型+投影文件放入 models\ 并重启服务，软件内刷新选择即可 |

## 附：术语对照

| 术语 | 含义 |
|---|---|
| ASR | Automatic Speech Recognition，自动语音识别 |
| VAD | Voice Activity Detection，人声端点检测（Silero 模型，判断一句话开始/结束） |
| PTT | Push-To-Talk，按住说话 |
| llama-server / llama.cpp | C++ 推理引擎，本地服务采用其 Vulkan 版 |
| Qwen3-ASR | 通义千问语音识别模型（本文档部署包内为 0.6B 量化版） |
| GGUF | llama.cpp 的模型文件格式 |
| mmproj | 多模态投影文件（把音频特征映射进语言模型，与主模型配套） |
| SSE / 流式 | 服务端增量推送结果；本地引擎支持 SSE 结果流式 |
| 热词 / prompt 偏置 | 转写时传入专有名词表，提升特定词识别概率（非强制） |
